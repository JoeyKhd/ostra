---
title: "The HTTP fallback"
description: "When a runner can't hold a WebSocket open."
---

A runner dials out to core and holds one WebSocket open, on core's address (`OSTRA_SERVER_URL`), so it works behind NAT and needs no open port. Some corporate proxies and firewalls refuse a WebSocket upgrade. For those, the runner falls back to plain HTTP: it posts its messages to core and waits for core's on a long poll. Both carry the same messages, so a task behaves the same either way.

## When it's used

When the WebSocket can't be opened, or keeps dropping, the runner switches to HTTP by itself within 30 seconds, and reconnects on its own after any drop.

## Choosing a transport

`--transport` (`OSTRA_RUNNER_TRANSPORT`) pins it:

| Value | What the runner does |
|---|---|
| `auto` | The WebSocket, falling back to HTTP when it can't hold one. |
| `websocket` | The WebSocket only, and reconnects on its own when it drops. |
| `http` | HTTP only, for a network that is known to refuse WebSockets. |

## Previews over HTTP

A task's previews work over HTTP with two limits, because a dev server's hundreds of module requests make a poor preview over long polls:

- **The browser view** streams at 2 frames a second, against up to 15 over the WebSocket. Clicks and typing still reach the page.
- **No tunnel:** no `ostra preview`, and no app in your browser on a preview domain, for that runner's tasks.

The preview pane and the CLI say when a task's runner reaches the server over HTTP only. See [Previews](/docs/using-ostra/previews#limits-by-network-and-version).
