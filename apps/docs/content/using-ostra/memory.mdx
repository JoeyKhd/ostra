Memory is a set of notes an organization or a project wants every task to know. Members keep them. An agent reads them and may propose new ones, but nothing it proposes reaches another agent until a member approves it.

## What it keeps

A note is one fact: a title, a short body, and a kind: convention, command, gotcha, decision, preference or term. It belongs to the organization or to one project, and records its source (a task, a review comment or a member) and its author. Notes are versioned and found with full-text search.

At the start of each session the agent gets a short index: each note's title and one line, within a size limit, and the notes marked **always** in full. It searches and reads the rest through ostra's memory tools, an MCP server in the box's sidecar with a token for that one task. The task page lists the notes a session read. Nothing is written into the repo.

The agent's search takes a question as it would ask it. Common words such as "how", "do" and "the" don't count, other words match their other forms ("tests" finds "test"), and the notes holding more of the question's words, closer together and in their title, come first. A path, a flag or an identifier, such as `packages/db/prisma/schema.prisma`, `--frozen-lockfile` or `OSTRA_CORE_URL`, matches as it's written. The agent then reads the notes it needs in full, up to 10 in one call, each checked against the task's organization and project.

Wherever a note reaches the agent, its text is quoted: the title in backticks and the body in a fence that no line of the note can close, with its headings and anything shaped like ostra's own markers escaped. A note can't add a section to the instructions or pass for an instruction from ostra, and a command in it reads as it was written.

The agent's own memory feature is turned off, so nothing an agent keeps for itself outlives the task.

## Editing it

The organization and each project have a **Memory** page, where members write, edit, delete and search notes.

- **Proposals.** Agents propose notes while they work, and members propose them with **Remember this** on a review comment or an AI review finding. A proposal waits on the Memory page, as a count, until a member approves it, rejects it, or merges it into another note. A proposal that contradicts a note is shown beside it.
- **Secrets are refused.** Every note is scanned when it's saved, and a note that holds a credential is refused.
- **No lost edits.** An edit made from a version that has changed since is refused, and your text is kept.

The index's limits are settings: `OSTRA_MEMORY_INDEX_MAX_NOTES`, `OSTRA_MEMORY_INDEX_MAX_KIB` and `OSTRA_MEMORY_ALWAYS_MAX_KIB`. See the [configuration reference](/docs/reference/configuration).
