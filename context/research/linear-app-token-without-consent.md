# Can ostra get a Linear app-actor token without a consent click?

**Status:** Research, 2026-11-19. Feeds ticket 08 (the app, OAuth and webhooks), ticket 27 (the connection), ticket 40 (the maintainer's steps) and spec section 3 of `context/specs/m2-tickets-in/spec.md`. Answers part of `trackers.md` S-1 (the client-credentials grant).

**Question.** Milestone 2's demo needs a Linear token that acts as ostra's own app user in `ostra-test`. The maintainer created the OAuth app (its client ID, secret and webhook secret are in `~/.config/ostra-dev/linear.env`), but nobody has clicked "Authorize" yet, and the maintainer is away. Can an agent get an `actor=app` token with no human click?

**Answer.** Linear has such a grant, but this app can't use it yet. One setting on the app has to be switched on first, and switching it needs a human or a credential that ostra doesn't have.

1. **Linear has a client-credentials grant that needs no consent.** "Client-credentials tokens use the `app` actor, are valid for 30 days, and do not include a refresh token", and "your server is expected to fetch a new token if it receives a 401 error" ([OAuth 2.0 authentication](https://linear.app/developers/oauth-2-0-authentication), "Client credentials tokens"). The request is `POST https://api.linear.app/oauth/token` with `grant_type=client_credentials` and a required, comma-separated `scope`, authenticated with the client ID and secret (same page). The page describes no authorization step for it, and the token can reach "all public teams in the workspace" (same page).
2. **The app has to allow the grant first.** "You must first toggle on client credentials tokens for your OAuth2 app when creating or editing the app in Linear" (same page). A manifest can ask for it too: `oauth.grant_types` takes `authorization_code` and `client_credentials`, and must include `authorization_code` ([OAuth application manifests](https://linear.app/developers/oauth-app-manifests); `spikes/linear-agent-mode/snapshots/linear-oauth-app-manifest.schema.json:138-166`).
3. **Run against `ostra-test` on 2026-11-19, the grant is off on this app.** A client-credentials request with the app's ID and secret and the scopes `read,write,issues:create,comments:create` returned `{"error":"unauthorized_client","error_description":"Client does not support the client_credentials grant type"}` (RUN, 2026-11-19, no token was issued).
4. **The setting can be changed through the API, but not with the key we hold.** Linear's GraphQL schema has `oauthApplicationCreate`, `oauthApplicationUpdate`, `oauthApplicationRotateSecret` and `oauthApplicationRotateWebhookSecret`. `OAuthApplicationUpdateInput.grantTypes` reads "OAuth grant capabilities the app may use. authorization_code is required. Omit to keep the existing grant types." (RUN, introspection of `https://api.linear.app/graphql`, 2026-11-19). The maintainer's personal API key can't call them: `oauthApplications` answered `Invalid scope: oauth:create required` (RUN, same day). We didn't find the `oauth:create` scope in Linear's public docs, so how a key gets it is unverified.
5. **The two grants replace each other.** "A client-credentials request replaces an existing authorization-code app installation", and "Requesting different scopes replaces existing app-actor credentials for that app in that workspace". To switch back, "revoke the existing authorization first" ([OAuth 2.0 authentication](https://linear.app/developers/oauth-2-0-authentication)). Adding or removing scopes "revokes existing app-actor tokens for that app in the workspace" ([OAuth actor authorization](https://linear.app/developers/oauth-actor-authorization)).
6. **The personal API key works for the plain API.** It is an admin in `ostra-test` (`viewer { admin }` is `true`). Milestone 1's adapter already reads, comments, moves statuses and links PRs with it (`../specs/m1-first-pr/spec.md`; `packages/adapters/adapter-linear`). It acts as the maintainer's own user, not as an app user.
7. **No Linear integration is installed on `ostra-test`.** `integrations(first: 50)` returned no nodes, so there's no GitHub integration either (RUN, 2026-11-19, with the personal key).

## What follows for milestone 2

- **The product keeps the consent flow** (spec section 11, items 2 and 3). The manifest asks for `authorization_code` only. The client-credentials grant has no refresh token, so demo step 8 (the access token expired and refreshed) can't run on it. And a client-credentials request made later would silently replace the installation a consent created (finding 5).
- **Tonight's demo uses the personal-key seed.** The scripted demo seeds the connection from `LINEAR_API_KEY`, as a development path only: reads, comments, status moves and attachments all work, as the maintainer's user. Ticket 40 and spec section 3 set out what it covers and what waits for the consent click.
- **The client-credentials path is a dev option for later.** Once someone with access switches the grant on (finding 2, one toggle on the app's page in Linear), ticket 08's `clientCredentialsToken` gets a 30-day app token with no consent, and the dev helper saves it in `linear.env` as `LINEAR_APP_TOKEN`. No refresh token comes with it. The consent flow, which demo step 1 needs, revokes it (finding 5).
- **Still open:** whether `app:assignable` and `app:mentionable` can be asked for with client credentials. The docs call them "App actor only" ([OAuth 2.0 authentication](https://linear.app/developers/oauth-2-0-authentication), scopes), which suggests they can, but nobody has run it. Also open: how a key gets the `oauth:create` scope. Both matter only for agent mode (milestone 6) and for app creation with no manifest click.
