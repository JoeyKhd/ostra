## Purpose

One press shows what happened in a run, step by step, without opening every output: each command's exit and time, each edit's size, each thought's gist. The outputs and diffs stay one more press away. The question doesn't get lost while the member reads: the pill says it's waiting and takes them back.

### Opening one more

- `output ›` opens the command's output under its row at the subject's x (`.out`, `states-steps.webp`, 3), and reads `hide output ›`. A failing command's output isn't opened for the member: the run's line already says it failed.
- `diff ›` opens milestone 1's diff block there.
- `show ›` opens the thought's full text, 14px `--muted`, with the same left line.
- Pressing the run's line again folds it all. Opening is per viewer, not saved, and survives new events arriving.

## The pill

The question block is below the thread's visible end. The thread's bottom 46px is a solid `--bg` band (an 18px fade above it), and in its middle the pill: amber dot, `Needs you · question`, `arrow-down`. Pressing it scrolls the block into view and focuses its first choice. It disappears once the block is in view. It never covers text: the text scrolls behind the band, and the band sits 12px above the composer, which doesn't move.

| Waiting | Pill |
|---|---|
| the question | `Needs you · question ↓` |
| the plan | `Needs you · plan ↓` |
| an approval (any member) | `Needs you · approval ↓` (`· 2 approvals ↓`) |
| any other block | `Needs you ↓` |
| a block for someone else (the watcher's quiet block) | no pill |

## Data it reads

The run's parts as `s1.md`; each tool part's start and end for its duration (content fix 3); the reasoning part's text for the excerpt (its first sentence, 120 characters at most); the turn's footer facts (`parts.md` part 6). The pill reads the open needs-you items the panel already has (`tasks.get` → `needsYou`) and the block's position in the scroll.
