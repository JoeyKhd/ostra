## Purpose

A member opening a running task sees, without reading a log: what they asked, what the agent said it would do, what it's doing this second and how far it is, and, when it stops to ask, the question with its choices. A failure that the agent fixed is one red word; it doesn't shout.

## Data it reads

- **The fold** (`packages/task-view`), per assistant message: `meta.at` (the time, the live step's clock), `meta.turnState`, the parts in order. The thread groups consecutive non-text parts into runs (content fix 1) and gives each run: its counts by kind, its first part's kind and duration (`Thought for 6s`), its failures with a `recovered` flag (`parts.md` part 4), and its approvals' receipts.
- **The live step:** the running part (`tool-*` with `state: input-available` or `preliminary`, a streaming `reasoning` or `text`) for its words; the turn's finished tool parts for `8 steps done`; the unrecovered failures for `1 failed`; `meta.at` for the clock.
- **A command's duration** (`4.1 s`, S4) needs each tool call's start and end in the fold (content fix 3).
- **The question:** `data-question` (`questionId`, `message`, `fields`, `status`), the elicitation's enum for the choices; `capabilities.answerQuestions` and the driver for the watcher's state.
- **The capture:** milestone 8's `data-attachments` item, `target.path` for the route, `width` for `1280`.
