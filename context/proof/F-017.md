## Notes

The machine milestones 1 and 2 are built on has no Docker, so nothing here has run a real box. The fake Engine API stands in for Docker, the external service; the live suite (`packages/adapters/adapter-executor-docker/src/docker.live.test.ts`) skips itself without Docker. The row stays `planned`.

- **Row 1 is partial:** the agent's container and the sidecar, on an internal network of the box's own, are shown against the fake Engine. The environment's services are F-094 (not built), and a real box is the live suite's.
- **Row 2, a bug found and fixed:** `createBox` for a box ID already in use failed on the name clash and then ran its clean-up, which removes a box by its ID: it removed the running box of the task that held it. It now refuses a box ID in use first, and touches nothing. The fake Engine now refuses a duplicate container name, as Docker does.
- **Row 3 is partial:** the agent's container spec holds no token, no token mount and no server address. Reading nothing from a shell inside a real box (environment, `ps`, files, network) is the live suite's, on Linux with Docker and the images built.
- **Row 4 is missing:** only a real Engine with the image pulled can time it. What proves it: a live test that times `createBox` to a ready sidecar.
- **Row 5 is missing:** not built. `createBox` makes each box's network from Docker's own address pools. What proves it: the pool in the executor, a test that makes 50 boxes' networks from it, then the live run.
- **Row 6 is partial:** the deadline on every bridge request is proved on the sidecar's real end of the bridge, with an init that never answers. That a stop then ends with the container removed is untested: `HostExecutor.stop`'s `killAll` rethrows the bridge's timeout, and the runner removes the box once the sidecar exits. What proves it: a live box whose init is frozen (`docker pause` of the agent's container) during a stop.
