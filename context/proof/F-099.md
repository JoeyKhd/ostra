- **Ticket 07 (2026-11-20)**, Linear's adapter: "Update ticket" writes the description through `issueUpdate(description)` (`updateTicket`), exactly as given, and refuses `acceptanceCriteria` as `invalid-input` before any call, since Linear has no field for them (`ticketFields.acceptanceCriteria: false`: core writes them into the description). A member's image goes through Linear's upload (`fileUpload`, a PUT of the bytes to the signed URL with only the headers Linear signed, then `attachmentCreate` with the asset URL), capped at 10 MiB (`MAX_ATTACHMENT_BYTES`); the fake Linear gained `fileUpload` and its upload target for this, and the file downloads back byte for byte. `defaultReadyStatus` drafts the board's "ready" status (the first `unstarted` one by position: "Todo" on `OST`). Sub-tickets are sub-issues (F-077). The rows stay `partial`: the draft, its editor and the "Update ticket" and "Mark ready" writes are core's and the panel's (tickets 15, 27, 34).
- **Ticket 09 (2026-11-20)**, OpenCode's adapter: `PrepareLaunchInput` gains `kind`, `allowPrototyping` and `tools` (additive, `@ostra/adapter-sdk`), and OpenCode's config maps them. A refine task's edits are denied after every ask unless its profile allows prototyping (the built-in Refine profile doesn't); the shell stays allowed, since the box contains it (ADR 0031), and `external_directory` stays denied last. ostra's tools the task's sets don't name are denied (`ostra_submit_draft` and the others), which OpenCode 2.3.2 takes as "not offered": they leave the model's tool list. OpenCode reports a shell command that exits non-zero as `completed`, with the exit in `rawOutput.metadata.exit`; the adapter now reads it as a failed call, so a push the fetch-only remote refused shows in the event log as a failed shell call. Ticket 04's team cases all run on the pinned OpenCode with the stub model, on both API formats (the fixture's `team` probes, `stub-scenarios.ts`), and the parity table names them for OpenCode.
