## Why every row is partial

- **The template and the commit style** (row 1): ostra reads each repo's PR template from GitHub, hands it to the runner in the spec, and puts it in the description of the agent's `set_pull_request_text` tool with "Follow it: fill in each of its sections". That the agent then fills it in is the agent's work: no run here had a repo with a template (`test1` has none, `demo.md` step 10). Nothing tells the agent to write commits in the repo's style, and when the agent leaves its work uncommitted ostra's own commit takes the task's title (the row's note). What would prove it: a live run on a test repo with a PR template and a commit convention, checking the PR's sections and the commit messages.
- **Each member whose prompt led to them** (row 2): the bot authors and commits every commit, and every co-author in the task's spec gets a trailer, on ostra's commits and the agent's own. But only the member who created the task is ever a co-author. A member who takes over as driver and sends the agent a message (`tasks.takeOver`, then `tasks.send`) gets no `TaskCoAuthor` row, and the runner's spec, read once at dispatch, wouldn't carry one anyway, nor would the hook's trailer file written at prepare. So that member's prompt can lead to commits without their trailer. This is a bug, not fixed here: the fix spans `tasks.send` (add the member), the runner (read the co-authors again before it commits) and the executors (rewrite the hook's trailer file), and milestone 2's ticket 17 reworks sessions across turns. A test that takes over, sends, and finds the second member's trailer on the branch would prove it.
- **The ticket** (row 3): the task's link is in every PR's footer; a ticket task's `Closes <KEY>` is milestone 2's ticket 18.
