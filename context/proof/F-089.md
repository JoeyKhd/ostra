## What is not proved yet

- **The agent's container** (row 1). On `host`, the agent's process gets the proxy's loopback URL and a fake key for its task only, and the real key is nowhere in its environment: proved. In a box, the agent is in its own container and the proxy in the box's sidecar, reached at `OSTRA_SIDECAR_HOST` (`apps/runner/src/run-sidecar.ts`). That needs Docker on Linux, which this machine doesn't have: `packages/adapters/adapter-executor-docker/src/docker.live.test.ts` and a task run in a box (F-017) would prove it.
- **Priced on their own** (row 6). The four kinds are counted and stored apart for each call, but nothing prices cache reads and cache writes yet: a model row holds an input and an output price only (`packages/db/prisma/schema.prisma`), the catalog keeps only those two (`packages/adapters/adapter-model-endpoint/src/catalog.ts`), and Home's spend (`sessionCost` in `packages/api/src/routers/home.ts`) prices fresh input and output and leaves cache reads and writes out, which were 88% of spike 10's tokens. It needs the two prices on a model (a migration), from models.dev's `cost.cache_read` and `cost.cache_write` or the admin's custom-model form, and the spend to use them (F-084, F-037).
- **The provider's own figure** (row 8). The demo measured the proxy against OpenCode's own count for the same calls, equal to the token (`demo.md`, "Tokens against the agent's own"). The independent check against a provider's own usage figure waits for an endpoint that reports one: the development endpoint doesn't.

**The demo's token checks read the stack's database** (row 8). They read Postgres directly, and used to take its port from `OSTRA_DEV_PG_PORT` alone, whatever stack the panel and core URLs named. A live run on 2026-11-19 against a stack on other ports, from a shell without that variable, read the default port's database, another stack's: "0 model calls; input 0, output 0, cache read 0", while the runner had logged six calls through the key proxy; the task wasn't in that database at all. The checks now read the dev database running in the demo's own checkout when neither `DATABASE_URL` nor `OSTRA_DEV_PG_PORT` is set, and the demo stops as soon as a task it started isn't in the database it reads. The record: `context/specs/m1-first-pr/demo.md`.

The live log is one call through the proxy to the development endpoint (`model.env`), counted within 2% of the usage the endpoint wrote into its answer; it prints no address and no key.
