Notes (2026-11-19, milestone 5's ticket 02): the executor contract gains the capability `registry` (`required`, `optional`, `none`), `create`'s `image` (by digest, with its pull credential) and `buildSnapshot`'s `push` and `digest`. No row is proved yet: the pushes and pulls themselves are tickets 09 (`docker`), 07 and 21 (`kubernetes`). The suite's case "F-120: a box from a registry image is pulled by digest with its credential, which is in no container's environment, files or process list; with no registry an image is refused" is what each of them passes: it failed when the tiny executor's fleet variant pulled by tag, when the pull token was written into the box's files, and when `refuseUnfitBox` let an image through on `registry: "none"`. Until ticket 09, `docker` refuses a build asked to push (`packages/adapters/adapter-executor-docker/src/docker-snapshot-box.test.ts` > "F-120: until docker pushes (ticket 09), a build asked to push to a registry is refused, and nothing is built"). The suite's cases live in `packages/adapter-sdk/src/testing/executor-suite.ts`, which isn't a test file, so they are named here rather than cited: `defineExecutorContractSuite` runs them in CI from `packages/adapter-sdk/src/contract-suites.test.ts` (the tiny executor and its fleet variant), `packages/adapters/adapter-executor-host/src/host-executor.contract.test.ts` and `packages/adapters/adapter-executor-docker/src/docker-executor.contract.test.ts`.

Notes (2026-11-19, milestone 5's ticket 06): the fake OCI registry (`packages/adapter-sdk/src/testing/net/fake-oci-registry.ts`, Basic or bearer auth, a push-only and a pull-only credential) is the registry tickets 09, 17, 21 and 28 test against; it proves no row by itself. Its tests (`fake-registries.test.ts`) failed when a credential could do the other's work and when a manifest's missing blobs were accepted.

Notes (2026-11-19, milestone 5's ticket 09): `docker` pushes and pulls. A build with `push` tags the scanned image with the registry's name and pushes it through the Engine API with the push credential in the call's `X-Registry-Auth` header (never `docker login`, so nothing lands in `~/.docker/config.json`), only after the scan found nothing (ADR 0038), and answers the registry's manifest digest. A box with an image pulls `ref@digest` with the pull credential the same way, before anything of the box is made, and its agent's container runs exactly that digest. The executor contract suite's case "F-120: a box from a registry image is pulled by digest with its credential, which is in no container's environment, files or process list; with no registry an image is refused" runs on `docker` (the fake Engine has no processes, so its process list is the live suite's). The second row stays `partial` for `kubernetes` (tickets 07, 21) and for the live case "F-120: an image pushed to registry:2 with the push credential is pulled by digest on a second Engine, and no credential is left in a file" in `packages/adapters/adapter-executor-docker/src/docker.live.test.ts`, run by ticket 35's Linux job. The third row stays `partial` until a real Docker host builds and keeps one (milestone 3's live `snapshot.live.test.ts`, ticket 35). The break-it for the third row: the test asserts `engine.pulls` is empty.

Notes (2026-11-19, milestone 5's tickets 07 and 08): on `kubernetes` a box's image is pulled by digest with a per-box `dockerconfigjson` secret (the executor contract suite's F-120 case passes on a pod in `packages/adapters/adapter-executor-kubernetes/src/kubernetes-executor.contract.test.ts`). A snapshot is built by a pod in the build namespace: the context step, rootless BuildKit exporting an OCI tarball (no push, no registry credential), milestone 3's scan, then the push step with the push credential, which only it mounts (`snapshots.ts`, `build-steps.ts`, `oci.ts`). The build test runs the pod on the fake cluster's process mode, with this package's own steps, a stand-in for BuildKit and ticket 06's fake registry. The rows stay `partial`: `docker`'s push and pull are ticket 09 and 21, the pool's refusal without a registry is core's (ticket 14, 17), and rootless BuildKit on kind is ticket 35's live run.
