## Notes

- **As they happen:** the e2e opens a running task in two tabs of the production build, then writes an edit of `docs/numbers.md` (+10) and a message to the database the way core's ingest does (rows, then one NOTIFY). Both tabs show the edit row with its file and counts, and the message, with no reload; then the rest of the session (messages, the push, the PR) arrives the same way.
- **The full history afterwards:** a reload mid-turn brings back every row and the partial text, and a reload after the session ended shows every tool row the tabs showed live, the edits with their files, the messages and the PR.
- **The same for every agent:** the page folds stored events only. The fold test runs a real turn with tool calls on each agent through its own adapter and ostra's ACP driver: the pinned OpenCode binary against a stub model, and the scripted fake ACP agent in both profiles (one declares the capabilities OpenCode lacks, one declares none). Each gives the same rows: the member's prompt and the agent's message, reads, edits with the files they changed, commands, and a failing read as an error. OpenCode is the only agent shipped (ADR 0032); a new agent adds its entry to `agents` in that test.
- The e2e runs at desktop width only (`@desktop-only`): it seeds its task once.
