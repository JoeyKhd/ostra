## Notes

- **Ticket 03 (2026-11-20)** built the code host's contract: `createReview` takes `event: "COMMENT"` by its type, so no caller can ask for an approval or a change request, and the fake code host refuses one that gets past the type. That proves the interface, not the review task: ticket 08 proves GitHub's adapter against it, and tickets 17 and 22 the review task end to end. The contract suite's cases (`code-host-suite.ts`) also check the line comments, the refusal of a line off the diff and `diffLines` on the fake code host; they can't be cited here, being in a suite file and not a test file.
- **Ticket 04 (2026-11-20)** added the agent side to the suite (`agent-team-cases.ts`, run on the scripted fakes): a review task's two repos at the given heads (one at an older commit), each folder's HEAD what the agent reads; and the reviewing fake's `submit_review` reaching the fake core's `/review` with its blocking finding and its nit by repo ID, `not-in-review` reaching the agent in the protocol's words, and a finding on a repo the task lacks refused before core is asked. Named in the parity table, not cited (a suite file). Break-its: reading the workspace's HEAD instead of each repo's failed the checkout case; answering a review as saved whatever the refusal switch said failed the review case.
- **Ticket 08 (2026-11-20)**, GitHub's adapter: `createReview` posts `POST /pulls/{n}/reviews` with `event: "COMMENT"`, the commit and each line comment by `line` and `side`. A bot's review of the same commit with the same body is looked for first, so a retry never posts twice. GitHub refuses the whole review with a 422 when a line isn't in the diff: the adapter then reads the diff's lines (`diffLines`, from milestone 3's compare) and answers `{ code: "line-outside-diff", commentIndex }` for the first comment off it, with nothing posted, so core can move that finding into the body and retry once. Live on `test1` (`github-adapter-m6-live.txt`): a review with one on-diff and one off-diff comment was refused, naming comment 1, with no review posted; the retry, with the finding in the body, posted one comment-type review with one line comment, read back on its line. **Found live:** `GET /pulls/{n}/reviews/{id}/comments` answers each comment's diff `position` only, with no `line` or `side`. So `listReviewComments` reads the PR's review comments (`GET /pulls/{n}/comments`) and keeps that review's, and the fake GitHub answers both endpoints as GitHub does. The row stays `partial`: the review task and core's post are tickets 17 and 22.
