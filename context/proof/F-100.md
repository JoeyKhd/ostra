## Notes

- **Ticket 03 (2026-11-20)** built the code host's contract: `createReview` takes `event: "COMMENT"` by its type, so no caller can ask for an approval or a change request, and the fake code host refuses one that gets past the type. That proves the interface, not the review task: ticket 08 proves GitHub's adapter against it, and tickets 17 and 22 the review task end to end. The contract suite's cases (`code-host-suite.ts`) also check the line comments, the refusal of a line off the diff and `diffLines` on the fake code host; they can't be cited here, being in a suite file and not a test file.
- **Ticket 04 (2026-11-20)** added the agent side to the suite (`agent-team-cases.ts`, run on the scripted fakes): a review task's two repos at the given heads (one at an older commit), each folder's HEAD what the agent reads; and the reviewing fake's `submit_review` reaching the fake core's `/review` with its blocking finding and its nit by repo ID, `not-in-review` reaching the agent in the protocol's words, and a finding on a repo the task lacks refused before core is asked. Named in the parity table, not cited (a suite file). Break-its: reading the workspace's HEAD instead of each repo's failed the checkout case; answering a review as saved whatever the refusal switch said failed the review case.
- **Ticket 08 (2026-11-20)**, GitHub's adapter: `createReview` posts `POST /pulls/{n}/reviews` with `event: "COMMENT"`, the commit and each line comment by `line` and `side`. A bot's review of the same commit with the same body is looked for first, so a retry never posts twice. GitHub refuses the whole review with a 422 when a line isn't in the diff: the adapter then reads the diff's lines (`diffLines`, from milestone 3's compare) and answers `{ code: "line-outside-diff", commentIndex }` for the first comment off it, with nothing posted, so core can move that finding into the body and retry once. Live on `test1` (`github-adapter-m6-live.txt`): a review with one on-diff and one off-diff comment was refused, naming comment 1, with no review posted; the retry, with the finding in the body, posted one comment-type review with one line comment, read back on its line. **Found live:** `GET /pulls/{n}/reviews/{id}/comments` answers each comment's diff `position` only, with no `line` or `side`. So `listReviewComments` reads the PR's review comments (`GET /pulls/{n}/comments`) and keeps that review's, and the fake GitHub answers both endpoints as GitHub does. The row stays `partial`: the review task and core's post are tickets 17 and 22.
- **Ticket 17 (2026-11-20)** built the AI review in core: `review.start` (`apps/core/src/review-loop/review.ts`, the domain's `startReview` in `packages/domain/src/review-loop/review.ts`) makes the code task's one review task the first time and reopens it per round, on every open PR's head, on the project's review profile (else the built-in Review profile), dispatched through the budget gate as an automatic round and only to a runner at minor 5; its spec carries `review { codeTaskId, round, repos }` and `tools: ["review", "memory"]` (`apps/core/src/dispatch/review-loop-spec.ts`). `POST /runner/v1/tasks/:taskId/review` (`apps/core/src/runner-http/review.ts`) takes a review task's findings with its task token, checked by the protocol's schema and capped; `review.post` posts one `COMMENT` review per PR, the findings on the diff as line comments and the rest in its body, a 422 on one comment moving it into the body once; earlier rounds' findings are marked resolved or outdated; blocking findings start a findings round, none sends the task on to its reviewer; a person's push during the review ends it. The prompt holds the acceptance criteria of the ticket's applied refine draft, else the ticket's own text. Rows stay `partial`: the read-only proxy and `submit_review` in the runner are ticket 22's, GitHub's adapter ticket 08's, the switch in the API and the panel tickets 28 and 35, and the live run ticket 39's.
- **Ticket 09 (2026-11-20)**, OpenCode's adapter. A review task's OpenCode denies every edit, whatever a rule asks, and keeps the shell (the box contains it). ostra's MCP server in OpenCode's list carries only the task's tool sets (`PrepareLaunchInput.tools`, the spec's `tools`): each of `submit_draft`, `submit_review` and `propose_environment` the sets don't name is denied, and OpenCode 2.3.2 leaves a denied tool out of the model's list. The case on the pinned binary serves all three from the fake core's MCP stand-in, as a server listing too much would: a code task's OpenCode offers none, a review task's `submit_review` only. **Break-it (the ticket's):** with the tool filter dropped from `buildPermissions`, both the binary's case and the config's unit case failed. Without the sets (a runner before milestone 6) the config filters nothing, since the sidecar serves only the defaults. The suite's review cases (`submit_review` round-trips, the checkout at two heads) run on OpenCode with the stub model, on both API formats.
- **Ticket 22 (2026-11-20)**, the runner. A review task's spec `review` puts each repo at its PR's head, detached: the host executor's checkout (`#checkoutReviewHead`, `packages/adapters/adapter-executor-host/src/host-executor.ts`, which `docker` and `kubernetes` run too) fetches the head and the base by SHA through the read-only git proxy, falling back to `refs/pull/<n>/head`, checks the head out detached and keeps the base as `refs/ostra/review-base`; a review reopened on a kept box moves each repo to the new round's heads. The test's heads exist upstream only as `refs/pull/<n>/head`, so a clone alone never has them. With two repos the agent starts at the workspace root. The runner pushes nothing after a review turn. `submit_review` maps each finding's `owner/name` to the repo's ID and forwards to core's `/review` with the link's token; a repo the task lacks is refused before core, and each of core's four refusals reaches the agent in the protocol's words. On `host` and on `docker` as a box's sidecar drives it. The rows stay `partial` for core's and the panel's parts and the live run (tickets 28, 35, 39).
