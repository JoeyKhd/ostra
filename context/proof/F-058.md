**Partial (ticket 21, 2026-11-19).** The site, its static export, its search and the configuration reference are built and checked; the reference lists every setting the code reads, with its default. The self-hosting guide, the runner pages and the adapter guide are skeletons that tickets 22 and 23 write, and the site is public once `docs.yml` has deployed it to GitHub Pages (ticket 34 enables Pages). `apps/docs/scripts/export.check.test.ts` reads the export, so it runs after `next build`, in `docs.yml` (`pnpm --filter @ostra/docs check:export`), never in `ci.yml`.

**Ticket 22 (2026-11-19).** The self-hosting guide (Start, Install, Run from source) and the runner pages are written. Every `sh` block marked `run` is extracted by `scripts/check-docs-commands.ts` and run, in the navigation's order, by the `docs-commands` job of `proof.yml` on a fresh `ubuntu-24.04`, against images built from the commit. The blocks without `run` need the reader's own values; a test checks that each names only settings, `ostra runner` flags and `pnpm` scripts ostra has. Still open for this row: the job's first run to a healthy stack, its log kept in `context/specs/m7-launch/demo/`, and the site published.

**Ticket 23 (2026-11-19).** The agents and models, using ostra, security, reference and contributing pages are written, the adapter guide among them. Its `ts` samples are compiled against `@ostra/adapter-sdk` in a test, and its worked secret store passed its kind's contract suite (7 cases) when run by hand. The CLI page is held to `ostra --help` by a test, both ways. The export check finds every page of those five sections built, written and linked from its section.
