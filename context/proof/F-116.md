Notes (2026-11-19, milestone 5's ticket 08): on `kubernetes` the baseline is a NetworkPolicy the runner chart applies (`baselineEgressPolicy` in `packages/adapters/adapter-executor-kubernetes/src/egress.ts` is its typed value, for ticket 23): it selects the box pods, allows DNS at the cluster's resolver, the server's address on its port (or the server's pods in the same cluster) and `OSTRA_EGRESS_ALLOW`, and the internet without the private ranges, the metadata address's link-local range, loopback and IPv6's private ranges, with no ingress. The executor never writes it; `health()` refuses a namespace without one, or with a policy that lets boxes reach the private ranges, and names the fix. The rows are `partial`: the shell probes from the agent's container, their positive controls and the control pod are ticket 24, and the enforcement on kind with Calico is ticket 35's run.

Notes (2026-11-20, milestone 5's ticket 24): the baseline is one list, `EGRESS_BLOCKED_V4` and `EGRESS_BLOCKED_V6` in `packages/adapter-sdk/src/executor/egress-baseline.ts` (spike 3's NetworkPolicy ranges: private, carrier-grade NAT, link-local with the metadata address, loopback, the reserved blocks, in IPv4 and IPv6). `docker`'s `egressRuleSet` builds from it a reject per range in `DOCKER-USER` and closes the host itself in `INPUT`, for IPv4 and, with the network's IPv6 subnet, IPv6, with the server's address and `OSTRA_EGRESS_ALLOW` as the only accepts; `deploy/egress-baseline.sh` applies exactly those (its test runs it with stand-ins for `iptables` and `ip6tables`). `kubernetes`'s `baselineEgressPolicy` (ticket 08) now takes its carve-outs from the same list. The rules reject rather than drop, so a probe sees a block at once and a timeout stays inconclusive; on `kubernetes` the network plugin's deny must be set to reject for the same (Calico's `iptablesFilterDenyAction`), which ticket 35's kind job sets. The probes (`packages/adapter-sdk/src/testing/egress-probes.ts`, ported from spike 3's `checklist.ts` and `box-network.ts`) are judged from scripted results here; from a shell in a real agent's container they are `packages/adapters/adapter-executor-docker/src/docker.live.test.ts` > "F-116: from a shell in the agent's container, every blocked range, the metadata address, the gateway and another box's sidecar ports are blocked, each after its control connected", run by ticket 35's Linux job, with kind and Calico, and a kind cluster without NetworkPolicy, for the control pod. Every row stays `partial` until those runs, and the canary's read in a real task's event log is the demo's (ticket 37).

Notes (2026-11-20, milestone 5's ticket 23): the runner chart (`deploy/helm/ostra-runner`) renders the baseline once per box namespace and the build namespace's policy, and `pnpm check:helm` compares each render with `baselineEgressPolicy` and `buildEgressPolicy` (`packages/deploy-checks/src/helm/rendered.test.ts` > "F-118: the baseline is egress.ts's policy, ranges and all, and the build namespace has its own", failing when a range is dropped or the server's exception widened). The build policy no longer writes a registry rule with no peers when no registry address is set, since a rule with an empty peer list allows every destination (`packages/adapters/adapter-executor-kubernetes/src/snapshots.test.ts` > "F-116: with no registry address and no hosts, the build policy allows DNS only: an empty peer list would allow every destination", which failed before the fix). Enforcement on kind with Calico stays ticket 35's.

Notes (2026-11-20, review fix): `docker` opened the server's address on every port, in `DOCKER-USER` and `INPUT`, while ADR 0029 (Q239) and ADR 0060 make the exception the server's address and port on both executors; on compose that address is the Docker host's gateway, so every sidecar could reach any service on the pool host. `EgressInput` now takes `serverPort`, the server's accept is TCP to that port only in both chains (in `ip6tables` for an IPv6 server), and `OSTRA_EGRESS_ALLOW` stays port-less; `deploy/egress-baseline.sh` takes `<server address> <server port>` and refuses anything that isn't a port from 1 to 65535. The cross-executor test checks both executors' server exceptions name the same port.
