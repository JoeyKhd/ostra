## Why two rows are partial

- **"in one flow and installs it"** (row 1): the server side of the manifest flow is proved against a fake GitHub (the state bound to the admin's session, the code traded for the App, its secrets stored, the connection made), and the panel's "Create a new App" tab is proved in the browser. The round trip through GitHub's own pages, where the admin confirms the App and installs it, needs a signed-in GitHub account in a browser: milestone 1's ticket 40, a maintainer's run (`context/specs/m1-first-pr/demo.md`, "What's still missing"). Its record, with the App it made and its installation, would prove the row.
- **"offers to finish it later"** (row 4): the panel says the App gets no webhook and names `OSTRA_CORE_PUBLIC_URL`, but nothing adds the webhook and its events to an App made without them once the address is public. Building that (GitHub's `PATCH /app/hook/config` with the App's JWT, and a button on the GitHub page) would let a test prove it.

## Live evidence

- `context/specs/m1-first-pr/live/f-006-workflows-push.txt`: a push of a `.github/workflows/` file to `ostra-test/test1` with the token a task gets (`contents: write`, `metadata: read`), 2026-11-19. GitHub answered "[remote rejected] (refusing to allow a GitHub App to create or update workflow … without `workflows` permission)" and made no branch. The git upstream stub's `refuseWorkflowChanges` answers in these words, and the host executor turns them into the task's reason.
- `context/specs/m1-first-pr/live/github-adapter-live.txt`: the GitHub adapter's live suite on the test org, 2026-11-19: the App has `checks: write` and `actions: read`.

## Bug fixed while proving it

- **A push GitHub refused said only "exit 1".** The host executor kept only the proxy's own `ostra:` lines from git's output, so GitHub's refusal of a workflow change was dropped and the task crashed with `pushing ostra-test/test1 through the git proxy failed (exit 1)`. It now says that GitHub refused the push because it changes a file in `.github/workflows/` and the App has no `workflows` permission, and for any other refusal it keeps the code host's reason (`packages/adapters/adapter-executor-host/src/process.ts`). The `docker` executor runs the same code.
