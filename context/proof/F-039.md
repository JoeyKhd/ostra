Notes (2026-11-20, milestone 5's ticket 22): the three Dockerfiles are buildable and checked, never built here (this machine is Windows with no Docker). `pnpm check:images` (`packages/deploy-checks/src/check-images.ts`) runs the static checks anywhere, and the package's tests run them in CI: every `FROM` pinned by tag and digest (the compose file's Postgres too), OpenCode installed at `OPENCODE_VERSION` with its scripts off and its binary checked by `sha256sum -c` against the literal sums `pinnedChecksums` holds (a sum computed in the build, or read from the package, fails), no secret-shaped `ARG`, `ENV` or `RUN` assignment and no token-shaped value, the server and the runner as `node` (uid 1000), the server's `HEALTHCHECK` through `ostra-server health`, the runner as `ostra` on the PATH, the base image's catalog as a file with the fetch and the update off, a box's start downloading nothing, and the compose file running exactly the tags `pnpm images:build` gives (`buildPlan`). `pnpm images:build` (`packages/deploy-checks/src/build-images.ts`) builds the three on Linux with Docker and prints their sizes; `--plan` prints the builds anywhere.

The first two rows stay `partial` until ticket 35's `live-docker` job builds the three images, records their sizes and starts each one: the server's `all` answering its health check, `ostra --version` in the runner printing the release, and the base image's OpenCode reporting 2.3.2 with the pinned checksum. Its log goes in `context/specs/m5-the-fleet/demo/linux/` and is cited here. Rows 3 and 4 are milestone 7's: nothing is published before then (ADR 0046).

Notes (2026-11-20, milestone 7's ticket 29): each image carries `/usr/share/doc/ostra/THIRD_PARTY_NOTICES`, every third-party package its install bundles with its license and the license and notice files it ships, written in its own build by `packages/deploy-checks/src/notices-main.ts` from `pnpm licenses list --json --recursive` (plus, in the base image, OpenCode's npm install and the models.dev catalog's MIT notice, `deploy/notices/`). The build fails on a license `scripts/known-licenses.ts` doesn't know, on a package in the install's store (`node_modules/.pnpm`) the notices miss, and, in the runner, on any OpenCode package left in its install, which the build removes (in a box the agent runs in the base image). `pnpm check:images` makes the three images' notices from this checkout's install and checks them against `pnpm list`, so a new dependency under an unknown license fails anywhere, before a Linux build. **The Linux proof job hasn't run** (this machine is Windows with no Docker): `scripts/live/docker.sh` now has `image-notices` (each image's notices: their count and first entries) and `runner-no-agent` (no `@opencode+cli` in the runner's store, no `opencode` on its PATH) after `images-build`, whose `docker build` runs the checks above. Its log goes in `context/specs/m5-the-fleet/demo/linux/` when the maintainer runs `gh workflow run Proof -f jobs=fleet`, and rows 1 and 2 stay `partial` until then.
