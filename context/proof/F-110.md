## Notes

- **Rows 5 and 6 are partial** (milestone 4's ticket 06): the index builder and the block's renderer, as pure code. That only a read moves a note's last use is ticket 15's `memory.used` ingest; that the block reaches the agent, ticket 07's.
- 2026-11-19, ticket 02 (m4): three rows are `partial`, for the adapter contract on the fakes. `AgentCapabilities.memory` (`mcp` or `index-only`), `PrepareLaunchInput.memory` (`{ block, tools }`) and `composeLaunchInstructions` (the profile's instructions, the repos side by side, the block); the scripted fakes call `memory_search`, `memory_read` and `memory_propose` on the MCP server their config names, a third fake is `index-only`, and `startFakeMemoryCore` (`@ostra/adapter-sdk/testing`) answers the sidecar's memory endpoints by the protocol's minor-3 schemas behind a stand-in for the sidecar's MCP server. The contract suite runs the same cases on every agent (`packages/adapter-sdk/src/testing/agent-memory-cases.ts`); the rows cite the fakes' own tests. OpenCode (ticket 07), core's endpoints and spec (ticket 15) and the sidecar's MCP server (ticket 20) prove the rest. The native-memory row stays `missing`: the base class states the rule and both fakes and OpenCode say they have none, and its contract case comes with the Claude Code adapter, the first agent with native memory.
