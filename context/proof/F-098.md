## Notes

- 2026-11-19, ticket 17 (m4): core's side. `addProjectRepo`, `removeProjectRepo` and `reorderProjectRepos` (`packages/domain/src/repos/project-repos.ts`); a reopen's new session gets a task repo, with no branch, for each repo the project gained (`addNewProjectReposInTx`); each PR ostra opens enqueues `pr.link-related`, whose handler (`apps/core/src/reactions/related-prs.ts`) sets every open PR's "Related" section from the host's current body and writes `pr.related_updated`. Row 1 waits on the runner's checkout of every repo (ticket 21) and the live run (ticket 41); row 3's diff and checks per repo are milestone 3's, still to be run with two repos (tickets 39, 41).
- 2026-11-19, ticket 21 (m4): the runner's side, on `host` and on `docker` as a box's sidecar drives it (`DockerExecutor` through the real bridge to a local init; the box's containers and volume on the Engine API are `box-dispatcher.test.ts` and `box-per-task.test.ts`, against the fake engine). Every repo of the spec is cloned in order into its folder under the workspace, on the task's one branch, with its own git token behind the git proxy; the runner checks the folders the instructions list are the spec's, each its own (`repo-folders.ts`); after a turn each repo that's ahead is pushed; a reopen on a fresh worktree fetches and applies each repo's hidden ref, and clones a repo new to the task at its base; the git proxy refuses another task's branch in each repo. With ticket 17's core side, rows 1 and 3 stay `partial` only for the live two-repo run (ticket 41) and the diff and checks per repo on the task page (ticket 39). Every break-it above failed its case on `host`; the clone, push, hidden-ref and token breaks failed the `docker` file's cases too.
- 2026-11-19, ticket 30 (m4): the API. `projects.repos` (anyone who can open the project) lists the repos in order with their branch-rule warnings and the unfinished tasks using each; `projects.addRepo`, `projects.removeRepo` and `projects.reorderRepos` (a project admin) call ticket 17's use cases, a refused removal naming its tasks; `projects.create` takes `moreRepos`, held to `OSTRA_PROJECT_MAX_REPOS`. Row 1 stays `partial` for the live two-repo run (ticket 41) and the screens (ticket 39).
