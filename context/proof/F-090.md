## Why three rows are partial

- **"through a proxy in the sidecar"** (row 1) and **"in the agent's container"** (row 3): this machine has no Docker, so every run here is on the `host` executor, where the git proxy runs in the runner's process on loopback and there is no container (ADR 0029 records that difference). The tests prove the proxy, the token it adds, and that no real credential is in the agent's launch environment, its task folder, the events or the logs. What would prove the rest: a task on the `docker` executor on Linux, with a search of the agent container's environment, files and process memory for the repo's token (F-017, `packages/adapters/adapter-executor-docker/src/docker.live.test.ts`).
- **"After every turn"** (row 5): milestone 1's session is one turn, and the runner commits and pushes what the agent left once that turn ends, which the cited test proves. A session that spans turns, with a push after each, is milestone 2's ticket 22 (`context/specs/m2-tickets-in/issues/22-runner-after-every-turn.md`); its test (three turns, the branch and the hidden ref after each) would prove the row.

## Bug fixed while proving it

- **The configuration reference didn't list the LFS hosts, and a GitHub Enterprise Server install had no way to list its own.** The GitHub adapter hard-coded GitHub.com's three storage hosts, and `docs/configuration.md` named none. `OSTRA_GITHUB_LFS_HOSTS` now sets them, with GitHub.com's as the default, core and the panel pass it to the adapter, and the reference has a line per code host and the sentence on cleaned-up tasks' LFS objects. The proxy also takes its cap on a refused push as an option (default 1 GiB), so a test can run past it.
