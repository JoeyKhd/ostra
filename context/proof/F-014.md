Notes (milestone 2's ticket 42, 2026-11-19):

- The Windows cases ran on Windows 11 x64 (the live log); CI runs the same unconditional tests on Linux, where the runner gets the process tree and the marker, or a cgroup when it has one. The job object's own two cases run on Windows only, so they are cited through the log. The three tests marked partial above all pass on both systems; what keeps the first row partial is that no run has had a delegated Linux cgroup, and the second that nothing has run on macOS (the ticket's Mac case) and the Linux case with the cgroup probe faked (`a Linux runner without a cgroup of its own` in `host-containment.test.ts`) runs on Linux only, behind a condition.
- The job object's case was broken on purpose: with the process tree in its place on Windows, the grandchild, the setup daemon and the killed runner's helper each outlived their task, and those three tests failed.
- CI's run on Linux, https://github.com/JoeyKhd/ostra/actions/runs/44450873472, passed the same tests with the runner's process tree and marker, and the Linux-only case with the cgroup probe faked.

Notes (2026-11-19, the long-path fix):

- The Windows-only case, `F-014: clones, branches, commits and pushes a checkout whose paths pass 260 characters (Windows only)` in the same file, runs behind a condition (the limit is Windows' own), so it is cited through its log; it makes a data folder and a checkout whose deepest file and branch-ref lock paths are each over 260 characters, and clones, branches, commits and pushes through the real host executor and the git upstream stub. The two cited tests run on every system in CI.
- `core.longpaths` does not lift git's own limit on the git directory itself (`'$GIT_DIR' too big`, at about 250 characters), so the data folder still has to be shorter than that. The data folder's layout, `<data folder>/tasks/<task id>/workspace/<checkout>`, is already shallow, so it was left as it is.
- The git proxy runs no git: it forwards git's HTTP calls. The git on its side of the wire is the agent's own, which uses the checkout's config, and that has `core.longpaths` too.

Notes (2026-11-20, milestone 5's ticket 10): on a `host` pool with a separate agent user, the marker sweep lists and ends that user's processes as that user (its `/proc` on Linux, `ps -wwE` on macOS, `kill -KILL` through `sudo -n -u`), since the runner can't signal them; on Linux with a delegated cgroup, `cgroup.kill` ends the unit whatever user its processes run as. The live cases are in `packages/adapters/adapter-executor-host/src/host-executor.live.test.ts` ("F-014: on Linux the task's delegated cgroup is killed as a unit: a detached helper of the agent's user ends with the task" and the macOS sweep's two cases), run by ticket 35's jobs.
