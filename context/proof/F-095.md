Notes (2026-11-19, milestone 5's ticket 02): the executor contract gains `capacity()` and `create`'s `size`; an executor without `boxSizes` refuses a size with `unsupported` and makes no box. The last row is `partial`: `host` counts slots only (above); `docker` enforces a size in ticket 09 and `kubernetes` in ticket 07, each through the suite's case "F-095: a box with a size gets exactly its limits, read back through the executor's own inspection; without box sizes a size is refused and no box is made", which reads the limits back through the executor's own inspection (`FleetFixture.limitsOf`). It passes on the tiny executor's fleet variant, and failed when that variant recorded 1 MiB more than the size, and when `refuseUnfitBox` let a size through on an executor without `boxSizes`. The suite's cases live in `packages/adapter-sdk/src/testing/executor-suite.ts`, which isn't a test file, so they are named here rather than cited: `defineExecutorContractSuite` runs them in CI from `packages/adapter-sdk/src/contract-suites.test.ts` (the tiny executor and its fleet variant), `packages/adapters/adapter-executor-host/src/host-executor.contract.test.ts` and `packages/adapters/adapter-executor-docker/src/docker-executor.contract.test.ts`.

Notes (2026-11-19, milestone 5's ticket 04): every organization has its three sizes with these limits, from the milestone 5 migration for the organizations that existed then and from the first admin's seed after it, one per name per organization. The first row stays `partial` until an admin can change them (`setBoxSizes`, ticket 27).

Notes (2026-11-19, milestone 5's ticket 07): `kubernetes` sets a box's size as its agent container's requests and limits, equal (Q236), and the sidecar's own fixed limits; `capacity()` offers the namespace's ResourceQuota less what its other pods request, or the runner's settings without one. The suite's size case passes on a pod in `packages/adapters/adapter-executor-kubernetes/src/kubernetes-executor.contract.test.ts`. The row stays `partial` until `docker` enforces a size (ticket 09) and a real cluster's cgroups hold one (ticket 35).

Notes (2026-11-19, milestone 5's ticket 09): `docker` enforces a size. The agent's container gets it as `NanoCpus`, `Memory`, `MemorySwap` equal to `Memory` and a `PidsLimit`; the sidecar and each service get the runner's fixed limits (`OSTRA_SIDECAR_*`, `OSTRA_SERVICE_*`); the tests read them back through the Engine's inspect, as `docker inspect` does. The executor contract suite's case "F-095: a box with a size gets exactly its limits, read back through the executor's own inspection; without box sizes a size is refused and no box is made" now runs on `docker` too (its fleet fixture in `packages/adapters/adapter-executor-docker/src/docker-executor.contract.test.ts`, the pool runner's half on the fake Engine). With `kubernetes` (ticket 07) both executors enforce a size against their fakes; the row stays `partial` because the limits read back from a running container's cgroup, with a stress held at them, are the live case "F-095: the size reads back from docker inspect and from the agent container's cgroup, and a stress is held at it" in `packages/adapters/adapter-executor-docker/src/docker.live.test.ts`, which ticket 35's Linux job runs. A runner's offer is its whole offer, the Engine's CPUs and memory less the reserve, as ticket 05 settled (core subtracts the boxes it placed, from its rows), so the runner doesn't subtract its live boxes a second time.

Notes (2026-11-20, milestone 5's ticket 13): the caps hold at admission, counted from `Box` rows under the pools' row locks; the project's default size reaches the box's row and the dispatch's `box.size` (`apps/core/src/dispatch/admission.test.ts` > "F-067, F-095: a runner's capacity is its slots, and where sizes apply its CPU and memory, counted from its boxes"). "A project picks its default" stays `missing` until the admin can set it (`setProjectPools`, ticket 27).
