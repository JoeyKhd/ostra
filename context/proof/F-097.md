## Notes

- **Row 2 is partial:** the "no ticket" half is proved, in a project with no tracker and in one with a tracker board (no ticket row, no tracker write, no ticket job). The two exceptions aren't built: there is no project setting that makes a ticket for a prompt task, and no "Create ticket" action. Both need a tracker, milestone 2 (the ledger row's own note). A test that turns the setting on, and one that presses "Create ticket" once, each making exactly one ticket, would prove them.
- Row 3: milestone 1 has no tracker at all, so every project works on prompt tasks alone. The core test takes a task made by `createPromptTask` in a project with no board through dispatch, the runner's events and the session-end reaction to an opened PR; the live demo did the same against GitHub (PR #31, from a project with no tracker).
- The e2e types the prompt into the New task page of the production build, picks the project the GitHub repo became, lands on the task page with the prompt as the first message, and reads the database (`apps/web/e2e/read-task.ts`): a `prompt` task, queued, with its session and its dispatch job, and no ticket anywhere.
