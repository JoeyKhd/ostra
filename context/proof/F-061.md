## Notes

- **Row 1 is partial.** What's proved is the token endpoint across one minor either way: a runner before minor 2, which sends no `x-ostra-minor` on its token request, gets minor 1's strict error body and its token; a minor-2 runner against a server at minor 1 hears no reason and retries a 401 instead of exiting; and a 403 from that server is still read as revoked. The window at `hello`, with the fix in its message, is tested in `apps/core/src/gateway/gateway.test.ts` ("connects runners one minor behind and one ahead, and refuses two ahead with the fix") and `packages/protocol/src/runner/minor-2.test.ts`; the first doesn't name F-061 yet, and neither has a break-it here. Milestone 5's compatibility matrix of runner N-1, N and N+1 against server N (ADR 0034) is what proves the whole sentence.

Notes (2026-11-19, milestone 5's ticket 06): the fake npm registry (`packages/adapter-sdk/src/testing/net/fake-npm-registry.ts`) serves a stand-in CLI at two versions with their integrity, for the pin (ticket 19); it proves no row by itself. Its tests run the real `npm install --registry` against it, and failed when the packument lost its integrity; a tarball that isn't the packument's is refused by npm with `EINTEGRITY`.

Notes (2026-11-20, milestone 5's ticket 16): row 1 is proved by the compatibility matrix over recorded frames (`packages/protocol/src/testing/recorded/minor-2.json` to `minor-6.json`, read through `@ostra/protocol/testing`'s `readRecordedBuild`): a server at minor 4 welcomes minors 3, 4 and 5 (5 is synthetic: minor 4 with one more optional field in `hello`) on the WebSocket and over HTTP, reads each one's frames at its minor and writes its dispatch down to exactly what that build recorded reading, and refuses 2 and 6 with `versionRefusalMessage`'s words: the runner's minor, the window, and "Update it to v<server's version>". Both halves run in `pnpm test`, so in `ci.yml`. Row 2 is `partial`: core's half, `GET /runner/v1/info` naming the server's version, its window and where to install from (a development core names `pnpm dev:npm-registry`; `null` until milestone 7 names the published package), is proved; the runner's install at start is ticket 19's. Row 3 is `partial`: a refused runner's row keeps its version and minor once, and `runnerRowVersionState` reads it as `outside` (`behind` once it updates to a build one minor back); the fleet view that shows it is tickets 26 and 31. `scripts/build-runner-at.ts` (tested in `scripts/build-runner-at.test.ts`) builds milestone 4's and milestone 3's runners for the demo's step 10, which runs them for real.
