## Batch listings (2026-11-20)

The dev endpoint lists each model twice, as `x` and `x:batch`, which the catalog match gives one name, so the pickers showed about 18 models twice. Not a "done when" sentence (the ledger row's note); its tests, each with its break-it:

- `packages/api/src/routers/providers.endpoint.test.ts` > "F-088: a provider's x:batch is kept unlisted beside x: at the add, when a refresh first finds it, and on every refresh after". Failed with the add's rows all listed (`addModelProvider`); with the refresh listing a catalog match it creates or updates, a custom model it creates, or a custom model it updates (`listed: true` in each of the three writes of `syncProviderModels`).
- `packages/api/src/routers/providers.endpoint.test.ts` > "F-088: a refresh hides a batch row an earlier version listed, and a choice on it moves to the plain row of the same provider". Failed with the call to `moveChoicesOffBatchRowsInTx` dropped from `syncProviderModels`: the project's model resolved to `not-listed`, so its tasks would not start.
- `apps/web/src/components/agent-profiles/model-picker-words.test.ts` > "F-088: two listed models of one name on one key show that key's endpoint IDs; on different keys, or with their own names, none". Failed with `disambiguatorsOf` setting nothing; with it ignoring whether the two share a key; and with it comparing a custom model by its display name instead of its endpoint ID.
