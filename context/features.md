# Feature ledger

Every feature we've decided on, with a checkable "done when". It is the source of truth for what to build and what is finished.

- **Priority:** `v1` (in the first release), `later`, `won't`.
- **Status:** `planned` → `building` → `done`, or `dropped`.
- **Rules:**
  - IDs are permanent: never renumber or reuse one. New features get the next free ID.
  - Change a status in the same commit as the work. Set `done` only when every condition in "done when" holds: each has a passing test named with its key, which CI runs (`F-025/c1: ...`, `AGENTS.md`'s "Proof"). A condition only a live run shows (Linux, macOS, kind, the e2e workflow) waits for the launch-gate Proof run, and its row stays `building` until then. *Changed 2026-11-21 (the maintainer: "keep tests, drop extras"): the proof files in `context/proof/`, their break-its and `pnpm check:proof` are gone; a dated note that cites a proof file is history.*
  - Specs in `context/specs/` name the feature IDs they cover.
  - A row that waits on an open question names it (`Q-nn` in `open-questions.md`). Its priority isn't final until that question is settled.
  - *(working value)* marks a number we expect to tune; changing it doesn't need a new ID.
  - The plan was signed off on 2026-11-17. A change to a v1 row's "done when" from then on is agreed with the maintainer and noted in the row.
  - `build-order.md` puts every v1 row in a milestone. A row names its milestone only where that matters to its "done when".
- **The rework of 2026-11-18.** The maintainer delegated every open question, and `history/answers-2026-11-18.md` answers them (section 4.3 for this ledger). Rows it changed carry a dated note naming the questions behind the change. Rows it added say "Added 2026-11-18". Two adjustments the maintainer made afterwards override that file: Claude Code (F-018) stays v1, in milestone 7, and signed runner downloads (F-085) come after v1. **The first was reversed on 2026-11-19:** Claude Code (F-018) moves after v1, and OpenCode is v1's only agent. The maintainer: "I think we agreed to only use Open Code, which is perfectly fine. So perhaps we can just skip Claude Code with its ACP for now." Rows that counted on a second agent in v1 carry a dated note.
- **Self-hosted only, 2026-11-19.** No hosted version is planned. The maintainer: "For now, forget that we will be selling this software as a cloud solution. It will only be an app that people self host themselves for now." A row that planned something only a hosted version needed carries a dated note (`history/self-hosted-only-2026-11-19.md`).
- **One organization in v1, 2026-11-19.** One team runs each install, with its clients as projects inside one organization. The lead proposed moving F-049's multi-organization features after v1, and the maintainer answered "sure". F-049 keeps v1's part (the organization in the data model, the one a fresh install starts with, and the isolation test), and the rest is F-134, after v1 (ADR 0026, amended).
- **Milestone 8, 2026-11-21.** The maintainer approved three features to land before the launch gate ("yes" to each): screenshots and recordings of the running app (F-121, moved forward into v1), live previews (F-140 to F-144), and a skills and MCP library (F-145, F-146). The double sidebar (F-147) is the maintainer's request the same day. `specs/m8-previews-and-library/` builds them.
- **Milestone 9, 2026-11-21.** The maintainer called attachments a top priority: files in the new-task box and in every message after it, and a ticket's whole content, its screenshots and documents included, as a task's context. The lead's proposal was accepted the same day. Files in messages (F-148), ticket files as context (F-149, extending F-064) and text out of documents (F-150) land before the launch gate. `specs/m9-attachments/` builds them, with ADR 0070.
- **Count:** 149 rows. 120 are v1 and 29 are later. The next free ID is F-151.

| F-002 | Accounts | Every account has a unique username and an email address. A member signs in with either one plus a password, through better-auth (ADR 0003).
