## What to build

- **A repeat `submit_review`** (content fix 6). In `submitReview`, under the review task's lock as now: when the review task's newest run is `submitted` or `posted` (this round's review is in), and its code task is still at that run's heads, answer `{ ok: true, reviewRunId, already: true }`, write no finding, enqueue no `review.post`, leave the run as it is, and append `review.submitted` with the run's `blocking`, `nits` and `repeat: true` to the review task's log only (the code task's thread doesn't hear of it). A run whose PR moved on, or a code task no longer in review, keeps its `not-in-review` refusal; too many findings keeps `limit-reached`.
- **The endpoint** (`apps/core/src/runner-http/review.ts`): answers through the protocol's `reviewAnswerFor(minor, saved)`, with the minor of the runner the call came from (`Runner.minor`, by the task's lease, or the `host` runner's own access token). A runner with no recorded minor counts as 8.
- **A free-text answer** (choice 5, content fix 11). `answerQuestion` and `checkQuestionAnswers` take `other: readonly string[]`: a select field named in `other` takes any non-blank words within `steerTextMaxChars`, a select field not in it must still be one of its options, and an `other` naming a field the question doesn't have, or a text field, is `invalid-input`. `question.answered` records `other` when it isn't empty. The `question-answer` command carries the words as the field's answer, as any answer. A late answer's prompt (`lateQuestionAnswerPrompt`) says which answers are the member's own words.
- **A draft's counts:** the use case that writes `draft.submitted` (milestone 6's `submit_draft` endpoint) adds the draft's `acceptanceCriteria` and `subTickets` counts, for the refine task's result line.
- **Read-only kinds' bookkeeping** (content fix 5): a refine or review task's session end raises no "ended without changes" needs-you item and records no PR outcome for it (check `recordSessionEnd` and its callers; change only what reads a read-only kind as a code task), and an empty `session.saved.repos` (ticket 06) reads as nothing unsaved. A review or refine task's reopen still restores its session archive.
- **Never logged:** an answer's words, the review's text, as before; the new log lines carry the IDs and `repeat`.

## Comments

- 2026-11-22, core: built as `✨ confirm a repeat review, take answers in words` (`53357adc`). Readings and differences:
  - **The repeat** (`submitReview`): a run `submitted` or `posted` is a repeat when its code task is `in_review`, at any sub-state (after a posted round it waits for its reviewer, or fixes the blocking findings until that turn pushes), and each of the run's heads is still the code task's PR at that head (the same `prNumber` and `headSha`). The order is wrong-kind, then not-in-review, then `limit-reached` and `invalid` (a repeat's findings are checked as a first hand-in's), then the repeat: no finding, no job, the run as it was, `review.submitted` with the run's `blocking`, `nits` and `repeat: true` on the review task's newest session, and a change notice for the review task alone. Its log line is `review.submitted` with `reviewTaskId`, `reviewRunId`, `blocking`, `nits` and `repeat`. A run that failed (a head moved under a submitted round) stays `not-in-review`, as does a posted round once a person pushes, or once the code task leaves review.
  - **The endpoint's minor** follows the ticket and the code both: the answer's minor is the lease's runner's `Runner.minor` (none recorded reads as 8), capped by the `x-ostra-minor` the sidecar's own request names (`teamLink` has sent `PROTOCOL_MINOR` there since minor 5, which is what ticket 01's comment pointed at). The cap matters because a `kubernetes` runner adopts its box pods across a restart, so an upgraded runner can still hold a minor-8 sidecar, whose strict schema would refuse `already`. A request without the header reads as minor 0 and gets `{ reviewRunId }`. `TaskContext` (`authorizeTaskCall`) gains `runnerId`, from the task token's claims or the `host` runner's access token, so both paths answer by the same runner.
  - **F-100/c2's test** changed with the behaviour: its second hand-in in the round is now answered as saved (`{ reviewRunId }`, since `postJson` names no minor) and writes no second finding, where it was `not-in-review`.
  - **Answers in words:** `checkQuestionAnswers(fields, answers, other = [])` and `answerQuestion`'s optional `other` (none when missing, so today's router compiles unchanged; ticket 08 passes it). `other` is deduplicated and kept in the question's order, at most `QUESTION_OTHER_MAX` (100, the event's cap), and refused when it names a field the question doesn't have ("An answer names a field the question doesn't have") or a text field ("Only a choice takes an answer in other words, and "{label}" isn't one"). Blank and over-long words are refused as any answer is. `question.answered` carries `other` only when it isn't empty, and the command's body is unchanged.
  - **The late answer's prompt** keeps its opening paragraph word for word (the panel's `readAgentMessage` finds it by its opening), adds one line after it, "An answer marked (in their own words) is what the member wrote instead of picking one of the choices you offered.", and marks each such answer's label in the `answers` block (`Channel (in their own words): …`). With no words it's the same prompt as before. `OWN_WORDS_MARK` is exported.
  - **A draft's counts:** `saveDraft` writes `acceptanceCriteria` and `subTickets` on `draft.submitted`.
  - **Read-only kinds:** the lifecycle already refused `session_ended` and `work_saved` for refine and review tasks, so neither raised the "ended without changes" item before; what read them as code tasks was the repo bookkeeping. `savesWork(kind)` (an exhaustive switch in `record-session-end.ts`) now keeps `recordSessionEnd` from reading their `session.ended` repos (no `withChanges`, no branch marked pushed, no `task.open-pull-requests`, the session ends `without_changes`), and `recordWorkSaved` from reading their `session.saved` repos; a review task's save then returns `unchanged` before the PR paths. The archive is still recorded, so a reopen restores the conversation. Nothing in core counted unsaved repos: the fold's `unsaved` counts repos without a hidden ref, so ticket 06's `repos: []` reads as 0 (ticket 02's `meta.saved`).
  - **Tests:** `apps/core/src/review-loop/repeat-review.test.ts` (the repeat submitted and posted, the refusals, the endpoint by minor on a task token and a `host` access token, and a review task's turn and session end against a code task's), `apps/core/src/ingest/plans-questions.test.ts` (F-151/c5, two cases, words with shell syntax and prompt-like text kept out of every log line), `apps/core/src/refine/refine.test.ts` (the counts), `packages/domain/src/prompts/agent-message.test.ts` (the late answer still reads as one).
