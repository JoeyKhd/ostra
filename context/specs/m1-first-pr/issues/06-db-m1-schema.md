# 06: DB: the milestone 1 schema and first migration

Status: resolved
Builder: contracts
Blocked by: 05
Features: F-002, F-086, F-088, F-013, F-050, F-097, F-023, F-030 (their data); ADR 0026 (organization scope), ADR 0027, ADR 0028
Packages: `packages/db`
Spec: `../spec.md`, section 5.3

## What to build

- The Prisma schema for every model in the spec's table, with the first migration. IDs are UUIDv7 text, generated by the database (`@default(uuid(7))`).
- better-auth's tables from its generator (`@better-auth/cli generate` against the plugin set ticket 30 uses: username, organization, device authorization, admin, bearer), with ostra's edits marked in comments, as spike 9 made them: username required and unique, a unique `(organizationId, userId)` on a membership.
- **Organization scope.** Every ostra model has `organizationId`. Every project-level model also has `projectId` and a composite foreign key `(projectId, organizationId)` to `Project (id, organizationId)` (ADR 0026, as amended).
- Task state as columns that map to the domain's union (ticket 07): a `state` enum, a nullable `subState` enum, and the fields some states need (for example `needsYouReason`). A check constraint keeps `subState` null outside `in_review`.
- `Event`: unique `(taskId, seq)` and unique `(sessionId, sessionSeq)`; `payload` is `jsonb`; an index for "a task's events after seq N". `Command`: unique `(runnerId, seq)`. `Runner.commandSeq` and `Task.eventSeq` are the counters taken under the row lock (ADR 0034, ADR 0035).
- Raw SQL in the migration: the `UNLOGGED` live-text table (one row per open segment), and the `NOTIFY` channel names as constants in `src/channels.ts`.
- `src/mappers.ts`: row-to-domain mappers that parse each ID column with its branded schema from `@ostra/protocol`.
- `src/testing/isolation.ts`: a helper that seeds two organizations and a restricted project, for every later test that checks isolation (spike 9's `isolation.ts` as the template).
